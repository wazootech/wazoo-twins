# eval-data

Held-out task data, baselines, and reports for the Ethan Davidson Twin (plan §5,
Phase 0 task 0.6 / Phase 1 task 1.7).

## What "held-out" means here

These tasks are held out in the sense that their **definitions were frozen
before any agent tuning and are never used in agent prompts** — the Twin never
trains on them. This is **not** wazoobench-style train/held-out separation: the
answers to these tasks live in the seeded World, and that is the point. The Twin
must retrieve them from the World, with citations. Do not mistake this for a
train/test split over the World itself.

## Files

- `tasks.json` — the serializable form of the task definitions (generated by
  `deno task eval` from `src/eval/tasks/`; the TypeScript files are the single
  source of truth, including the `verify` functions, which cannot be
  serialized). 25 held-out tasks (10 briefing, 10 draft, 5 scheduling)
  - 20 smoke questions when run with `--smoke`.
- `baseline.json` — the current baseline report, against the **real** seeded
  World (recorded Nov 6, 2026; see "The real baseline" below). Phase 0.6 records
  scores before any agent work, so Phase 1 has something to beat honestly.
- `baseline-synthetic.json` — the first baseline, against the synthetic
  in-memory world (25/25). Preserved for the audit trail; it measures the
  harness, not the Twin.
- `latest.json` — the most recent eval run's report (written when a baseline
  already exists), compared against `baseline.json`. Only same-world comparisons
  are verdicts: the runner skips the regression verdict when
  `baseline.world !== report.world`.

## The real baseline (recorded Nov 6, 2026)

`baseline.json` is the **real-World baseline**: held-out set run against the
seeded libsql World (`~/workspace/wazoo-twins-data/world.db`, 1,642 facts at
probe time) via `createWorldClient`, with the retrieval-only answerer.

- **Held-out: 24/25 (96.0%)** — 10/10 briefing except `brief-07-john-sync` (see
  below), 10/10 draft, 5/5 scheduling.
- **Smoke: 18/20** (`deno run ... src/eval/smoke.ts --world real`).
- **Provenance failures: 0. Unapproved actions: 0. Draft approval proxy: 100%.**

Known gaps found by this baseline (all retrieval/coverage, not harness bugs —
the harness correctly reported them):

- `brief-07-john-sync` — the John Carlo Manuel sync facts (Wednesdays 9:30am,
  Sundays 6pm, blog.wazoo.dev) were not in the retrieved top results.
- `smoke-06-albert` — "Journeyman" missing from the answer even though the real
  World contains a Journeyman-banner Deadline fact mentioning Albert Davidson:
  the keyword search did not rank it into the answerer's top 8.
- `smoke-14-purav-meetup` — "Airoma" missing: `search("Purav Patel Airoma")`
  returned 0 hits, so the Airoma Cafe meetup detail is either not yet seeded or
  not indexed.

Caveat: the seed was **still being written** when this baseline was taken
(`world.db` grew between runs; one earlier real smoke run hit
`SQLITE_BUSY:
database is locked` mid-run as the seed builder wrote).
Re-baseline once the seed settles. Do not treat this snapshot as final.

## The synthetic baseline (read before quoting numbers)

The first baseline was run against a **synthetic in-memory world**
(`src/eval/synthetic-world.ts`): 30 hand-written facts grounded in `~/MEMORY.md`
and the opportunity tracker, served through the same `WorldClient` interface the
real World uses. It scored 25/25 with 0 provenance failures and 0 unapproved
actions, and is preserved at `baseline-synthetic.json`.

Consequences:

- **Synthetic-baseline numbers measure the harness, not the Twin.** A high
  synthetic pass@1 means the harness, verifiers, and retrieval-only answerer
  work end to end. It says nothing about the real Twin.
- Every report records `world: "synthetic" | "real"` and a `worldNote` saying
  which world it ran against. Do not present synthetic numbers as real baseline
  numbers.

## Metrics

- `pass@1` overall and per kind (briefing / draft / scheduling / smoke).
- `provenanceFailures` — answer claims with no citation. Target: zero.
- `unapprovedActions` — attempted actions outside the read/draft tiers. Target:
  zero. Any count above zero FAILS the run.
- `draftApprovalProxy` — fraction of draft tasks whose every factual claim is
  cited and whose deterministic checks pass. This is a **proxy** for "approvable
  without edits", **not** a human approval rate: no human reviewed these drafts.
  The real approval rate is measured in Phase 1 (task 1.4) from Ethan's actual
  approvals.

## Commands

- `deno task eval` — full held-out set (25 tasks) against the synthetic world.
- `deno task eval --smoke` — held-out set + 20 smoke questions (45 tasks).
- Full held-out set against the real seeded World — needs `--allow-sys`,
  `--allow-ffi`, and `--allow-write`, which the `deno task eval` flags do not
  grant, so run it directly:
  `deno run --allow-read --allow-env --allow-net --allow-sys --allow-ffi --allow-write src/eval/run.ts --world real`
  (add `--force-baseline` to overwrite `baseline.json`).
- `deno task smoke` — the 20 smoke questions only (synthetic world by default;
  `--world real` needs the same direct-run flags as above).
- `deno test src/eval/` — unit tests (synthetic data only, no network).
